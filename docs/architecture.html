Overview

What it is, and the one goal that shapes it

claude-replay reads an agent's session transcript — a JSONL log from Claude Code or Codex — and replays it as a readable, foldable stream: user turns, assistant prose, thinking, tool calls with their results and diffs, sub-agent spawns, attachments, slash commands. It is read-only and fully testable without a terminal.

Every structural decision serves one goal: the engine knows nothing about presentation, and almost nothing about any specific agent. That makes the parser reusable by any frontend, and makes "support a new agent" a bounded, local change instead of a sprawl across the codebase.

Boundary

Two crates, one compiler-enforced line

The workspace splits into the engine and the presenters. The split isn't a convention — it's enforced by the dependency graph.

claude-replay-core

The engine. Its only dependencies are serde_json + anyhow — no ratatui, syntect, clap, or HTML. So it cannot reach a presentation dependency; "the core is presentation-agnostic" is guaranteed, not merely intended.

claude-replay (root)

The presenters + CLI: the ratatui viewer, the HTML export, the agent-jdi supervisor. Depends on the core and re-exports its modules under their original paths, so viewer code reads as if the split weren't there.

The three layers

Decode → fold → present

Parsing is a pipeline; each layer has exactly one job. The only place that knows a specific agent's raw format is Layer 1.

L1 — decode (agent-specific)

claude_model / codex_model map that agent's raw line shapes onto a single canonical Message vocabulary (UserText, Thinking, ToolUse, ToolResult, Command, Attachment, …). Different agents name things differently; the L1 decoder is the only code that knows those names. Nothing downstream ever parses a raw agent format.

L2 — fold (shared)

The Replayer folds the message stream into the Block render model — joining each tool result onto its call, grouping thinking turns, coalescing activity runs, resolving the queued-prompt lifecycle, stamping per-turn times. It is agent-agnostic; the four points agents genuinely differ are isolated in a small Shaping seam. Hundreds of lines of fold logic are written once and shared — that's what the canonical Message between L1 and L2 buys you.

L3 — present

The viewer, the HTML export, and --dump consume the Block stream. They never see a Message or a raw line — so a bug in one presenter can't be a parsing bug, and all three share one source of truth for classification and diff rendering.

Data model

Everything a presenter needs is a Block

The presenter-facing vocabulary is small and stable. A Session is the whole parse; its blocks already have results joined onto calls, and nothing is dropped or truncated — what shows collapsed is a view decision, not a parse decision.

Alongside the blocks, a Session carries a SessionIndex (turns / sub-agents / tool counts / attachments, computed in one scan so presenters don't re-walk), a Metrics tally, and the session cwd. Block classification is one function — block_kind — projected two ways: a coarse fold_key (grouping) and a fine HTML class (styling), so the TUI and HTML can never disagree on what a block is.

The per-agent seam

One trait, one registry

Everything that varies by agent lives behind TranscriptAdapter, resolved through a two-function registry — adapter(agent) to dispatch, adapters() to iterate. There is no match agent scattered through the engine.

The whole-file parse is a provided method: it composes scan_join_ids → the streaming fold → the metrics accumulator. So a new agent supplies only the small per-agent hooks and gets batch and live parsing for free. The agent-jdi supervisor mirrors this exactly with its own adapter trait + registry.

Scale & liveness

Streaming parse, incremental follow

Transcripts can reach hundreds of megabytes, so parsing streams — one line resident, two passes, never a whole-file Vec<Value>.

  • One-shot — parse_session(path) auto-detects the agent and returns a whole Session. parse_session_as skips detection; the _enriched variants also load the sub-agent tree.
  • Live tail — FollowParser::open(agent, path) holds a persistent Replayer; each poll() folds only newly-appended bytes — O(delta), no re-read — and is proven byte-identical to a full re-parse at every append. A truncation/rewrite (compaction) resets and rebuilds.
// the entire surface a library consumer needs
let session = claude_replay_core::parse_session(path)?;      // one-shot
let mut f = claude_replay_core::FollowParser::open(agent, path); // live
while let Some((blocks, times, metrics)) = f.poll()? { /* re-render */ }
Extending

Adding an agent

The payoff of the design: a new agent (say Gemini) is a *_model / *_metrics / *_discover trio plus one impl TranscriptAdapter row. The shared engine is never touched.

  1. Register — add the Agent::Gemini variant + label.
  2. gemini_model.rs — the L1 decoder: decode_line, scan_join_ids, and a GEMINI_SHAPING const. The only place that knows Gemini's raw format.
  3. gemini_metrics.rs — a small token/cost accumulator (reuse TimeSpan + estimate_cost).
  4. gemini_discover.rs — where Gemini keeps transcripts: candidates_scoped + resolve_id.
  5. impl TranscriptAdapter — a unit struct delegating to the three modules; inherit the provided/defaulted hooks.
  6. Register the row — one arm in adapter() and one entry in adapters().
  7. Test it — an L1 equivalence gate + a FollowParser round-trip; then the usual fmt / clippy / test.
What you did NOT touch: the fold, the Block model, Session/SessionIndex, the discovery facade, the live follower, or any presenter. sniff makes auto-detect recognise the format; the registry row makes it reachable everywhere.
Confidence

Testing & the invariants it holds itself to

Headless TUI

All view state lives in View, driven under ratatui's TestBackend — assert cells in an in-memory buffer, no terminal. A tmux e2e covers the real binary.

Byte-identical refactors

The streaming parse is pinned bit-identical to frozen oracle parsers, and every refactor is checked with --dump / --dump-html diffs on frozen Claude + Codex transcripts.

Crate boundary

The core's dependency set makes a presentation import a compile error — the agnosticism can't rot.

One classifier · one fold

Block classification and the L2 fold exist once; per-agent differences live only in decode_line + Shaping.
