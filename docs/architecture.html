The transcript engine
behind claude⁠-replay

A read-only replay of AI coding-agent sessions — and underneath it, a library built on two promises: the engine is agent-agnostic and presentation-agnostic (adding an agent or a whole new frontend touches no shared code), and it is lean by design — a live million-line session costs the server O(open turn) RAM and each frontend a viewport's worth of rendered state.

§1

Five crates, three levels of reuse

Every boundary is enforced by the dependency graph, not by review — so each claim below is a compile-time fact.

claude-replaythe thin assembly binary: CLI + the agent-jdi supervisoreverything above

Level 1 · core alone

Parse and analyze transcripts in any program. The whole dependency bill is serde_json + anyhow.

Level 2 · core + present

Build a new frontend — native app, service, notebook. Cache, protocols, folding, summaries and highlighting come ready-made.

Level 3 · the finished UIs

Embed the TUI (app::run) or the HTML exporter/server (dump_html · dump_all_html · serve) from your own binary.

§3

The sans-io heart

The engine's core does no I/O. SessionAccumulator is a push-based fold — you acquire bytes however you like and push lines in; every parse path in the workspace is this same fold, differing only in who feeds it.

// the one seam every path shares
let mut acc = SessionAccumulator::new(Agent::Claude);   // or ::with_store(agent, store)
acc.advance_at(byte_offset, &line);                      // push one line — that's the I/O boundary
let session = acc.snapshot();                            // the current Session, any time

§4

Your frontend decides what a block is

Session<BV> is generic over its per-block value, and the BlockStore seam hands that decision to the presentation layer: the block itself, a locator, auxiliary state, a pointer into a file you maintain — anything written once, as the block commits.

InMemoryStore

BV = Block — identity. Batch parsing and owned Session snapshots.

TierBStore

BV = Deferred — a 12-byte locator; serde bytes spill append-only to disk. Lossless (BlockRead).

ArcStore

BV = Arc<Block> — the cache retains the one authoritative copy; readers hold references. The TUI live path: single-copy content, resync served from memory.

RecordStore html

BV = RecordLocator — put renders the block to its wire-format JSON record as the side effect. The Session is the projection.

The showcase. The live HTML server's committed zone is stored exactly once — as rendered wire records. A /pull renders only the open turn; everything committed is answered with a {offset, len} pointer that clients range-read straight off the log. A thousand committed blocks and a three-block open turn cost a poll three blocks of render and the client one pread. And because a wire record is a one-way projection, RecordStore deliberately does not implement BlockRead — the type system keeps every whole-session consumer off it.
§5

One data layer, both frontends

SessionCache<P, F, A> answers “which sessions exist, which are materialized, in what representation, with what derived state attached” — and its three parameters are the three choices a frontend makes without giving up generality or efficiency.

pollowned Session snapshotF = InMemoryStore2O(session)
poll_deltafull blocks + changed_fromF: BlockRead2 + transientO(session) alloc
poll_arcsplice-shaped Arc deltaF = ArcStore1 — cache-owned, view-referencedO(delta)
pull (cursor)zones + byte-range pointersany P1 (0 in RAM w/ RecordStore)O(open turn)
 
// the TUI's instantiation (app.rs)
type TuiCache = SessionCache<
    TierBStore,     // pull tier: unused
    ArcStore,       // cache owns; View references
    ViewSidecar,    // evicted frames park heights,
>;                  //   folds, scroll — warm reloads
// the HTML server's (serve.rs)
cache: SessionCache<
    RecordStore,    // committed IS the wire form
    InMemoryStore,  // /stream baseline
    ServeAux,       // titles · parents · baselines
>

The aux slot is the third seam: a per-session home for derived, view-parameter-dependent state that put-once storage can’t hold. The TUI parks an evicted frame’s measured geometry and interaction state there and re-adopts it on return — same width and shape means no re-measure, and your fold/scroll state survives. The cache stays opaque; the consumer owns validity.

§6

Lean, twice over

Memory is one idea applied at every level: each representation lives only as long, and only as wide, as its consumer needs. CPU is two ideas: borrowed threads, and delta-only protocols.

transcript bytesresident: none — a byte-offset tail reads only deltas
canonical Message~one line's worth, transient
Block · open turnO(turn) in the accumulator
Block · committedyour store's choice: RAM · disk locators · rendered wire records · handed off entirely
presentation formTUI: heights + prefix sums (O(N) small ints) · HTML: JSON records + an on-disk record log
rendered resultTUI: ~96 styled blocks near the viewport · HTML: DOM window of viewport ± 1500px
  • No thread waits for work. The TUI tails on its input loop's idle tick; the HTML server folds on the client's request thread — an idle page is an idle server, and a closed page costs nothing after the 30 s reap (evicted residents hibernate and restore without re-folding).
  • Every consumer speaks deltas. In-process, poll_arc hands the view Arc clones of each committed block with an O(turn) changed_from — content stored once, cache-owned, search runs over it. Cross-process, the 4-tuple cursor travels with each request, so the server is per-client stateless — N windows read one shared log at their own pace. Both halves of that protocol ship in Rust (pull / PullClient), and the pull client is the executable spec the embedded JS mirrors.
  • Refactors can't drift. The streaming parse is pinned byte-identical to frozen oracles, the follower to a full re-parse at every append, and every change runs a frozen-fixture gate that must print BYTE-IDENTICAL: PASS.
§7

Adding an agent

Everything that varies by agent sits behind one trait (TranscriptAdapter) in a tiny registry. A new agent is three small files and one impl — the shared engine is never touched. Calibrate by the three that exist: Claude (flat sub-agent directory), Codex (operation-scoped child rollouts), QoderWork (its format matches Claude's, so its whole adapter is discovery plus a sniff — zero new parsing code).

  1. agent.rs — add the variant and its labels.
  2. gemini_model.rs — the decoder: raw lines → canonical messages, plus a 4-hook Shaping. You are writing a decoder, not a parser.
  3. gemini_metrics.rs — a small token/cost accumulator.
  4. gemini_discover.rs — where its transcripts live on disk (home-scoped, like the rest).
  5. adapter.rs — one impl TranscriptAdapter row; sniff returns ownership (Owns / CanParse / No), so a merely-compatible file is labeled, never mislabeled.

Detection, the picker, live following, both frontends, and the byte-identical equivalence gates pick the new agent up with no further changes.
