    02 · 它是什么

    全机范围的会话索引，查看器内置其中

    它扫描本机上每个智能体的转录存储——Claude Code、Codex、Qoder、QoderWork——并只提供一个页面：左侧是会话栏，右侧是你选中那个会话的实时视图。

    agent-monitor 与 agent-monitor-v2 两个二进制共用同一个库的一半，各自都能提供两套外壳；它们可以在不同端口、不同缓存根目录下并排运行。

    • 只读，且只走环回地址。它按智能体写入的原样读取转录，只监听 127.0.0.1；默认启动时在 2727 端口打开应用壳。
    • 刻意的惰性。会话在监视器自己缓存根目录下的持久条目，只在访问它时写入，从不靠全盘扫描——机器上有几千个会话，索引依然便宜。
    • 两套外壳，都受支持。应用壳（一个文档直接消费结构化索引与记录流）是默认；经典的“侧栏 + iframe”页面保留到应用壳在真实使用中被验证为止。两者各有一个切换按钮，选择记在 <state>/ui.json；?ui=classic 或 ?ui=app 只覆盖一次请求，不改动记忆。
    • 有意只管一台机器。一个文件系统、一张进程表。多机由 agent-monitor-fleet 负责：每台机器一条 SSH 隧道，加一个切换页，各标签页就是那些监视器自己的页面，原样嵌在 iframe 里——每个监视器的端口从它自己的锁文件读出，从不猜测。

    04 · 对会话采取行动

    回应那个正在等你的会话

    在页面里输入的提示会被注入到智能体自己的终端窗格。这是对一个运行中进程的写入，所以监视器把它当作安全面来对待——而且只有一份实现。

    • 配对。写路由需要配对令牌；它设置的 cmauth cookie 以主机为作用域而非端口，因此一台机器上的两个监视器共用一个状态目录来存放令牌、口令和授权。
    • 同意。按窗格授权，再加一道口令；“这条提示可以注入到那个窗格吗”这个判断——会话到窗格的归属，以及两种发送通道——只存在一处，在库的那一半里，两个前端都调用它。
    • 只走环回。页面从不离开本机；fleet 页面只能通过你自己打开的 SSH 隧道触达远端监视器。

    库的这一半回答什么

    index扫描，以及发送判断：哪个会话住在哪个窗格里
    consent授权与口令
    control配对令牌与两种发送通道
    state共享的状态目录：令牌 · 口令 · 授权 · ui.json
    05 · 它如何构建

    一条数据通路，监视器是它的最后一级

    agent-replay 工作区里的一切都是同一条流水线上的一级。特定于智能体的代码只存在于解码级；其上每一级都与智能体无关、与呈现无关，而 crate 边界让箭头只能这样指。

    一个子智能体块会指名一份子转录，它递归地走同一条流水线——这条回到“发现”的边，正是会话栏里家族聚类的来源。

    发现哪些会话存在、属于谁、如何分组engine · core
    读取有界省略的行读取器：兆字节级的行从不驻留内存LineSource
    解码一行原始日志 → 规范消息，按智能体TranscriptAdapter
    折叠结果归位、片段合并、已提交 ∣ 开放轮次的切分Replayer
    存储每个已提交块只写入一次，存入前端选定的存储BlockStore
    呈现会话缓存、拉取协议、线上记录present · html
    监视索引、外壳、控制面claude-monitor

    06 · 实时

    实时，却没有一个尾随线程

    没有线程在等转录增长。折叠在发出请求的那个页面的请求线程上推进——页面空闲，服务器就空闲；页面关闭后不花任何成本，直到 30 秒回收。

    • 每个被跟随的会话只占 O(开放轮次) 的内存。完成的轮次越过一道持久性前沿、一次性写入存储；只有开放轮次会随事件到来而重新推导。
    • 已提交内容一生只发送一次。html crate 的 RecordStore 在每个块提交时就把它渲染成线上记录，追加进只写日志；页面自己按字节范围读取这份日志——磁盘上一份序列化，内存里零份，读者数量不限。
    • 下一次运行接着上次继续。持久条目保存已提交块与元数据流，后续进程从上次停下的地方折叠，而不是从第 0 字节开始——在一份 107 MB 的转录上实测，99.99% 的内容不再重读。

    每个会话的驻留层级

    已登记~0

    智能体 + 路径——被发现但未打开的会话的默认状态

    实时驻留O(open turn)

    一个 SharedSession：开放轮次 + 各种表；空闲 30 秒后回收

    持久bytes on disk

    监视器根目录下磁盘上的已提交流与元数据流；闲置两周后清除

    07 · 线上协议

    四个数字的游标，服务器不保存任何客户端状态

    每个请求都带着读者的完整位置。已提交内容是纯追加；只有开放轮次会重发，而它的重写只是提升一个代号，而不是重发整个世界。

    Cursor { epoch, committed_id, provisional_gen, provisional_index }
    // the whole position, in every request
    已提交区

    这个读者在只追加日志里读到了哪里；以指向记录日志的字节范围指针形式提供

    临时区

    开放轮次的代号，以及读者在其中的位置；一次回填或一次定稿会提升代号，页面替换这个很小的区域

    • 每个区只有一条规则：截断到 from，再延伸。两个半边都用 Rust 实现——服务端的 pull，以及作为可执行规范的 PullClient——内嵌页面在共享的 record-stream.js reducer 里逐个转换地镜像它。
    • Epoch 是会话有效性：截断或重写会提升它，过期的游标从零重新同步，由保留的副本提供——从不重新解析。
    • N 个标签页、卡顿的标签页、新加入的标签页，都按各自的节奏读同一份共享日志。
    08 · 数据层

    一个会话缓存，前端要做的三个决定

    SessionCache<P, A, E> 是任何呈现层赖以构建的一层：哪些会话存在、哪些驻留、以何种表示、附带什么派生状态、每个会话的持久条目如何守护。监视器的三个回答：

    TUI 用 ArcLog、一个视图边车和逐会话条目实例化同一个类型；--no-cache 选择 Transient——仍是真正的缓存，只是不持久。同一个类型，两个前端。

    P · 实时存储RecordStore

    已提交块就是线上记录——存储与会话是同一个对象，不可能失步

    A · 边车ServeAux

    一次性写入的存储装不下的、按会话的呈现状态：标题、父级、基线

    E · 条目SingleWriter

    监视器启动时一次性认领整个缓存根目录，于是逐条目的锁不会有竞争、干脆不存在；第二个监视器在任何缓存产生之前就被重定向到第一个

    09 · 环回上的安全

    链接只能做页面提供过的事

    被服务的页面会链接到转录触及过的文件。每条提供出去的路径都用 HMAC 签名（密钥在 <state>/file-sig-key，权限 0600），每种能力一枚戳——于是路由只对提供过的东西起作用，而一个“显示”链接无法被改成读字节。

    /file
    文件戳

    把字节渲染进页面——只为渲染策略允许的路径铸造；不盖戳本身就是限制

    /__reveal
    显示戳

    在文件管理器里打开该路径——不交出任何字节，所以总会铸造，也是任何内容都不内联渲染的页面上点击唯一能做的事

    • 哪些路径可以渲染是一项设置，<state>/render-policy.json：never、offered（文件不存在时的默认）或带目录列表的 allowlist。它折进渲染风味里，所以改动它会触发重新渲染，而不是继续提供按旧策略盖戳的页面。
    • 发现的范围限定在 $HOME 之内。位于其外的 cwd 什么都不探测，探测也从不触及 $HOME 自己的 slug，所以被行为不端的智能体污染的存储不会泄漏进另一个目录的列表。
    10 · 可复用 · Rust 的一半

    库的一半：一份实现，两个前端

    claude-monitor 既是库也是二进制。agent-monitor-v2 在同一组模块之上组合出另一个会话页面——“是一个前端，不是第二份实现”——第三个前端需要的一切都已经是公开的。

    模块它回答什么
    index对每个智能体存储的扫描、会话卡片及其状态，以及发送判断——哪个会话归属于哪个终端窗格
    consent授权存储与口令：谁可以向哪个窗格注入
    control配对令牌与两种发送通道
    cost按会话、按家族的令牌与成本汇总，子智能体折入其根会话
    state两个监视器共同读取的状态目录：令牌、口令、授权、记住的外壳
    routes路由表——后端一半与前端一半——加一个分发器，新外壳添加页面时无需重新决定路由能做什么
    ui记住的外壳选择、?ui= 覆盖，以及包含共享模块在内的静态资源服务
    11 · 可复用 · 前端的一半

    七个共享模块，一份源码，三个消费者

    侧栏、拼接壳和应用壳曾经各自复制同一套逻辑。现在每个关注点只在 claude-replay-html/src/html/shared/ 里存在一次，至于它如何到达页面，是消费者自己的事。

    模块它负责的关注点
    session-visibility家族（根会话及其子智能体）、隐藏与忽略、哪些行和组可见
    state-labels状态词汇及其提示措辞，来自跟踪器的类型化原因
    keymap所有页面共用的一张按键表，以同样的方式解析
    reading阅读偏好——等宽、宽幅——加载并应用，而不会被意外持久化
    capabilities双戳规则：根据路径携带的戳决定预览、显示还是复制
    control-protocol面向控制面的撰写、发送与撤销，含口令提示
    record-stream游标、拉取与记录查询，以及镜像 PullClient 的 reducer
    • 原样服务：作为 ES 模块在 /monitor-ui/shared/<name>.js 提供给应用壳。
    • 内联进每个自包含页面，置于页面脚本之前，脚本通过 window.__shared 读取——离线导出与在线会话视图一视同仁。
    • 两条约定，由测试守住：共享模块不导入任何东西，并以恰好一行 export { … } 结尾；新增一个模块只是表里加一行，导入闭包测试与约定测试覆盖其余。
    12 · 可复用 · 更底下的层

    三个入口，从最小的开始

    监视器是工作区库最大的消费者；同样的各层向任何程序开放。按任务选依赖。

    只用 coreserde_json + anyhow

    + presentcore + syntect

    构建一个前端：会话缓存、双半边的拉取协议、折叠策略、摘要与高亮——原生应用、机器人、笔记本组件

    + tui / html成品查看器

    从你自己的二进制里嵌入终端查看器，或 HTML 导出器与实时服务器

    13 · 保持诚实

    每次改动都过门禁，浏览器是门禁之一

    整个工作区无需终端即可完整测试，而监视器的行为——定位、增长中的搜索、尾部钉住、虚拟 DOM——由真实引擎的用例针对两套外壳钉死。

    排队中的 bug 的复现以 known_red_<task> 命名签入并被门禁跳过；修复时去掉标记。经典页是衡量应用壳的行为基准。

    门禁它守住什么
    fmt · clippy · test · doc格式、零警告、每个 crate 的确定性测试套件、拒绝警告的 rustdoc
    字节一致门禁一组冻结的转录经 dump、HTML 导出与打包写入器渲染后与基线比对——重构必须打印 BYTE-IDENTICAL: PASS
    node 契约每个前端模块按 ESM 解析；共享模块与其消费者之间的接缝在源码层面断言
    浏览器测试台密闭的 Chrome 用例——临时存储、临时状态、一个实时追加记录的驱动器——在经典页与应用壳上跑同一个场景：增长中钉住与不钉住的阅读、搜索计数、新消息药丸、排队提示、盖戳的显示
    无 TTY 的 TUI视图在 ratatui 的 TestBackend 下驱动；可选的端到端运行在私有 tmux 服务器内
