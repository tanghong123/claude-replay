Build on the
claude⁠-replay library

Three ways in, smallest first: analyze transcripts with the core crate alone, build your own frontend on the shared data layer, or embed the finished TUI and HTML viewers. Every example on this page is how the shipped binaries actually consume the library — none of it can rot into pseudo-code.

core deps: serde_json + anyhow sans-io — you own the bytes live protocol: both halves in Rust html frontend: zero terminal deps
§1

Build, test, gate

The workspace is fully testable headless — no TTY anywhere in the default suite. Four checks gate every change:

cargo build --workspace
cargo fmt --check
cargo clippy --all-targets      # no new warnings
cargo test  --workspace         # deterministic; every crate
scripts/gate/gate.sh            # frozen-fixture diff → must print BYTE-IDENTICAL: PASS

The gate renders a frozen transcript set through --dump, --dump-html and the bundle writer and diffs against a baseline — engine refactors must be output-preserving, and intentional changes are reviewed line-by-line then re-baselined.

§2 · level 1

Core alone: read transcripts as data

One call parses any supported agent's session into an agent-neutral Session — blocks, per-turn times, token/cost metrics, and a derived index.

use claude_replay_core::{parse_session, Block};

let session = parse_session(Path::new("session.jsonl"))?;   // agent auto-detected
println!("{} blocks · {} turns · {}",
         session.blocks().len(), session.index.turns.len(), session.metrics.footer());
for block in session.blocks().iter() {
    if let Block::ToolUse { name, target, .. } = block { /* tally tool usage… */ }
}

For anything incremental — or any I/O the library shouldn't dictate — drop one level to the sans-io SessionAccumulator and push lines yourself, from a file, a socket, an mmap, or a test vector:

let mut acc = SessionAccumulator::new(Agent::Claude);
for line in my_source_of_lines() {
    acc.advance_at(offset, &line);        // one line resident at a time
}
let session = acc.snapshot();
  • Storage injection. with_store(agent, TierBStore::file(path)?) spills committed content to disk as it folds — RAM stays O(open turn) plus a 12-byte-per-block locator table; read blocks back through BlockAccess.
  • Delta reads. stream_read(from) hands a live consumer committed[from..] + the open turn — never an O(N) rescan.
  • Live tail. FollowParser::open(agent, path) bundles a byte-offset tail with the accumulator; poll_delta() reports changed_from so your renderer re-derives only the tail.

Runnable: cargo run -p claude-replay-core --example parse -- <transcript> [--follow]

§3 · level 2

Your own frontend, on the shared data layer

claude-replay-present is the layer that makes a new presentation cheap. Its centre is SessionCache<P, F, A> — pick the pull tier's block representation, the follow tier's, and your sidecar type; the capability bounds then pick your protocol menu for you.

the in-process shape — what the TUI does

Borrow your UI's idle tick; never spawn a follower thread. With the ArcStore follow tier, the cache retains the one authoritative copy of the blocks and your view holds Arc references — a tick costs O(delta) refcount bumps, and a resync-from-zero is served from memory:

type MyCache = SessionCache<TierBStore, ArcStore, MySidecar>;
let cache = MyCache::new();
cache.register(&id, Transcript::open(agent, path));
loop {
    if no_input_for_250ms() {
        if let Some(Ok(d)) = cache.poll_arc(&id) {
            view.splice(d);            // keep [0..frontier), append delta + open turn,
        }                              //   re-derive from d.changed_from
    }
    cache.reap(30_000);                // idle residents fall back to registrations
}

the decoupled shape — a thread or a network away

Serve PullReplys from a SharedSession on one side; hold a PullClient on the other. The client owns the cursor, so the server is per-client stateless — N windows work for free:

// server side (any transport)
let ss = SharedSession::open(agent, path);
ss.advance()?;                // borrow-to-tail
let reply = ss.pull(request_cursor);
// …send `reply`…
// client side
let mut pc = PullClient::new();
let applied = pc.apply(&reply);
if let Some(d) = applied.first_changed {
    rerender_from(pc.blocks(), d);
}   // next request carries pc.cursor()

choose your BV — the BlockStore seam

The presentation decides what the Session stores per block. The one constraint: a BV is written once, as its block commits — so it must not depend on interactively-changing view parameters (measured heights belong in the cache's aux sidecar instead, which is invalidatable).

impl BlockStore for MyStore {
    type Bv = MyPerBlockValue;                    // what Session.committed holds
    fn put(&mut self, b: Block, at: BlockIndex,
           user_times: &[Option<EpochSeconds>]) -> Self::Bv { /* once per commit */ }
    fn reset(&mut self) { /* source truncated */ }
}
  • BlockRead — implement iff your Bv can reconstruct its Block. Everything that rebuilds block streams bounds on it, so the compiler tells you exactly which consumers a one-way projection can't feed.
  • PersistentStore — backing length + reopen (+ optional state hooks), so SharedSession can hibernate/restore around your backing across evictions.
  • The worked example — the HTML crate's RecordStore renders each committed block to its wire record at put time; /pull then answers committed zones with byte-range pointers and the serving path renders only the open turn.
§4 · level 3

Embed the finished frontends

// the terminal viewer
claude_replay_tui::app::run(&args, &path)?;
claude_replay_tui::app::run_interactive(&args)?;
// or drive view::View under TestBackend
// the HTML frontend
claude_replay_html::dump_html(&args, &path)?;
claude_replay_html::dump_all_html(&args, &path)?;
claude_replay_html::serve(&args, &path)?;

Args is plain data (Default + struct literal) unless you enable the cli feature for clap parsing — a headless service can call dump_all_html with a hand-built Args and never link clap. The shipped claude-replay binary is itself just ~60 lines of dispatch over these calls.

§5

Add an agent

A new agent is a decoder, not a parser: three small files + one adapter impl, and the shared engine is never touched.

  1. register — the Agent variant and its labels.
  2. decode — map raw lines onto the canonical Message vocabulary; wire the 4-hook Shaping (tool build, result join, orphan policy, turn grouping).
  3. meter — a small token/cost accumulator.
  4. discover — where transcripts live on disk; scope cwd probes with ancestors_below (strictly inside $HOME).
  5. wire — one impl TranscriptAdapter row. sniff returns ownership (Owns / CanParse / No) and store_contains adds provenance, so compatible-but-foreign files get labeled, never claimed.
  6. test — a frozen-fixture equivalence gate + a follower round-trip (incremental == full re-parse at every append).
Cost floor. QoderWork's format matches Claude's, so its entire adapter is discovery plus a sniff — zero new parsing code. That is the design working as intended.
§6

Testing a TUI with no terminal

  • Deterministic (preferred). Drive view::View under ratatui's TestBackend: render to an in-memory buffer, call the view's methods, assert cells. All viewer state lives in View, separate from terminal wiring, precisely so this works.
  • End-to-end. A private tmux -L server drives the real binary with send-keys/capture-pane — opt-in via cargo test --test tmux_smoke -- --ignored.
  • Quick plain check. claude-replay <path> --dump - renders the whole transcript to stdout through the same View pipeline — ideal in a pipe.
